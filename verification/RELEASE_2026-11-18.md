## Delivered implementation

- Controller-approved background/music synchronization: authenticated manifest
  and file endpoints, SHA-256/size checks, automatic background selection,
  2 GiB bounded cache, reuse, corruption repair and obsolete/partial cleanup.
  The cache counts toward the worker resource budget. Original library assets
  remain on the controller; no source library or credentials are transferred.
  Retries retain the original manifest/version and automatic background choice.
- Independent host-side YouTube OAuth consent with PKCE and loopback callback.
  Existing tokens cannot be overwritten; Drive-only consent is rejected.
- Publisher edits for queued/failed items before any remote session/video exists,
  including correction of elapsed schedules. Channel authorization is enforced.
  Known video IDs reconcile without reopening expired sessions. Verification
  checks successful upload status, channel, privacy and the exact scheduled time.
  Known quota/permission failures produce sanitized, actionable diagnostics.
- Highlight fallback prefers sentence endings/pauses within duration limits;
  selected candidates retain their actual LLM/heuristic provenance and model.
  This is a boundary improvement, not a validated claim of editorial quality.
- Malformed LLM windows no longer skip semantic analysis of later windows.
  One GPU plan/model is retained during ranking, explicitly unloaded afterward,
  and bounded by a 60-second crash TTL. GPU timeouts/errors receive one CPU retry.
- The GPU overlay selects the bundled CUDA 12 Ollama backend. On the actual
  4 GiB card, a Qwen 3B probe measured 16.94 tokens/s at 24 layers versus 59.33
  at 36, with sampled peaks of 1465 and 2047 MiB. Only the tested model receives
  36 layers automatically, and only with at least 3500 MiB free. Other models
  keep the earlier cap. These are simple probe results, not a general throughput
  guarantee. Backend selection follows the supported
  [Ollama troubleshooting setting](https://github.com/ollama/ollama/blob/main/docs/troubleshooting.mdx).
- Separate VP9/Opus ranged downloads now explicitly merge to MP4. The real source
  initially produced `selected.mp4.mkv` and failed the expected-path check;
  a real two-stream HTTP fixture and a real 58.64-second YouTube range both pass
  after the fix (1280×720, 3515 decoded frames, audio present).
- Explicit source attribution survives queue edits. Invalid title/description
  markup and descriptions exceeding the documented
  [5000 UTF-8 byte limit](https://developers.google.com/youtube/data/reference/rest/v3/videos#snippet.description)
  fail before upload; multilingual text is not silently truncated.
- Fresh-start data-directory initialization with independent scratch paths,
  Windows hook rendering with an explicit installed font, LF checkout rules for
  Linux shell wrappers, and the missing remote-store source-cleanup query.
- Decoded AAC peak checks exposed +0.3 dBFS overshoot on controlled speech.
  Final-rate stereo formatting, a latency-compensated limiter without makeup
  gain, and 192 kbit/s AAC corrected that rerender to −4.7 dBFS true peak at
  −16.7 LUFS. A decoded transient regression and real Linux/Windows renders pass.
- Aligned installed Remotion packages at 4.0.545, Zod 4.6.7 and Mediabunny
  1.66.0 using the package's recommended auxiliary versions. Patched the Vite
  build/dev chain to 6.4.6 with the compatible React plugin. Both Factory and
  retained upstream UI builds pass; an actual Vite dev proxy returned page 200,
  unauthorized API 401 and authenticated API 200.
- Browser verification found a narrow-panel overflow caused by the navigation's
  grid minimum. Zero-minimum grid tracks and a shrinkable sidebar fix it without
  changing the application structure. Actual document/scroll widths now match
  at 568 px and 1265 px; the temporary desktop viewport was restored afterward.

## Startup and delivery

Exact Windows instructions: [PC B setup](../docs/PC_B_WINDOWS.md).
Run `scripts/setup-factory.ps1` once in each checkout. On PC B, set the ignored
`.env` to the controller's private/Tailscale URL and token, a distinct worker ID,
and appropriately authorized read-only Drive credentials. Upload approved assets
once on PC A. Detailed credential/mount policy: `docs/FACTORY_DEPLOYMENT.md`.

```powershell
# PC A
docker compose -f docker-compose.yml -f compose.gpu.yml --profile controller up -d --build
# PC B, after its one-time private connection/Drive configuration
docker compose -f docker-compose.yml -f compose.gpu.yml --profile worker up -d --build
```

UI: http://localhost:5175 . CPU fallback remains available by omitting the GPU
overlay. Pull Qwen once through Settings on PC A and `docker compose --profile
worker exec ollama ollama pull qwen2.5:3b` on PC B.

The authenticated GitHub account has no push permission on the target repository.
Delivery uses an authorized fork/feature branch and a pull request; it must not
be reported as a merge to upstream main. Remote commit and CI are verified
separately from local checks. Raw job manifests, Google IDs, credentials, signed
URLs, generated videos, screenshots and model files remain ignored locally.
