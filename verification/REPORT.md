## Що реалізовано

- Автоматичні метадані через наявний локальний Ollama/Qwen: три варіанти назви,
  опис, теги, хештеги, категорія, окремі мови аудіо й метаданих, авторство.
  Непідтверджені твердження відхиляються; після однієї корекції використовується
  чернетка з тексту уривка з обов’язковим переглядом.
- Версії, фактичний текст уривка та історія ручних правок у SQLite. Чернетки
  зберігаються у Drive-маніфесті й доступні після локального очищення.
  Зміна чернетки скасовує схвалення та зупиняє ще не розпочату публікацію.
- Окремі технічні та редакторські перевірки: декодування, розміри, звук,
  кліпінг/тиша, чорні кадри, межі слів, контекст, дублікати й авторство.
  Успішний MP4 сам по собі не вважається редакторськи якісним матеріалом.
- Publisher передає повні метадані та звіряє їх із реальним YouTube API.
  Ідентифікатор відео зберігається до перевірки. UNCERTAIN не створює дубля;
  для відомого video ID є окрема перевірка через GET без нового завантаження.
- Календар враховує IANA-часовий пояс каналу, денні ліміти, мінімальний інтервал
  і переходи літнього часу. Нові версії чернеток зберігають правила планування.
- Обкладинки з реальних кадрів із перевіркою різкості/освітлення та положенням
  тексту. API-статус обкладинки відокремлено від результату завантаження відео.
- Окрема read-only авторизація Analytics, прогрес і дата синхронізації, денні
  перегляди, watch time, тривалість/відсоток перегляду, реакції й підписники.
  Lifetime та метрики періоду не змішуються; недоступні показники залишаються null.
- Спостереження за мовою/форматом/тривалістю/джерелом потребують достатньої
  вибірки. Вони не змінюють правила каналу й не обіцяють охоплення.
- Усунено проблему пошуку FFmpeg під час часткового WebM-завантаження Windows.
  FastAPI/React, Drive, ASR, стилі монтажу, Kokoro та структура worker збережені.

## Реальні перевірки

**YouTube — PASS для приватного завантаження.** Власник окремо дозволив один
10-секундний приватний тест із голосом Kokoro та субтитрами. Створено одне відео;
назва, опис, теги, категорія, обидві мови, канал і приватність звірені через API.
Теги стали доступними із затримкою: спочатку UNCERTAIN, потім успішна GET-перевірка
того самого ID. Повторного відео не створено. Публічний реліз і реальний native
schedule не виконувалися: такого дозволу не було. Їхні протоколи перевірено fixtures.

**Обкладинка — PARTIAL.** Реальний JPEG із кадру тестового відео створено та
збережено на Drive. Після завершення обробки відео YouTube відхилив встановлення
обкладинки для цього каналу/відео. Статус ASSET_ONLY відображає відмову; це не
позначено як успішне встановлення. JPEG залишається доступним для Studio.

**Analytics — PASS для доступу, PARTIAL для рекомендацій на реальних даних.**
Окремий read-only token дійсний. Синхронізація READY, один реальний відеозапис,
30 денних рядків звіту. Недостатньо історії для рекомендацій: INSUFFICIENT_DATA.
Impressions, CTR і retention curve не вигадуються. Позитивного впливу на
перегляди чи якість рекомендацій на великому каналі не заявлено.

**Три послідовні завдання — PASS.** Власний 20-секундний матеріал, оригінальне
аудіо/Crop, Silent/Blur та Longs із двох послідовних інтервалів. Усі READY,
cloud_verified=true, метадані від Qwen, локальні робочі файли видалені після
перевірки Drive. Час: 105,80 с; 100,39 с; 121,47 с. Shorts: 1080×1920; Longs:
1280×720. Silent не містить аудіодоріжки. Редакторський статус NEEDS_REVIEW
збережено, автоматичного схвалення або публікації не було.

**Браузер — PASS.** Окремий headless Chrome із зібраним production frontend та
копією фактичної тестової бази відкрив Dashboard/Create/Jobs/Editor/Library/
Publisher/Analytics/Settings. Збереження версії скасовує approval, історія
доступна; JavaScript errors: 0. Особисті вкладки користувача не використовувалися.

**GPU.** Цей ПК: NVIDIA RTX 3050 Laptop **6 GB**, один важкий етап за раз,
модель вивантажується між етапами. Логи Ollama підтвердили offload 36/37 шарів
Qwen на GPU. На запущеному controller активний один локальний воркер. Попередній розробник перевіряв інший ПК із
4 GB — його результати збережені як історичний baseline, не приписані цьому ПК.
Новий багатогодинний 4 GB benchmark не заявлено.

**Тести — PASS.** Повний Windows-прогін: 128 passed. Після додаткових перевірок
черги — 30 publisher tests passed. Linux factory + retained MIT modules:
286 passed. Перші Linux-помилки були спричинені CRLF у робочій копії shell-файла;
після нормалізації до наявного LF-правила всі перевірки пройшли.

**Twitch — PASS для bounded E2E.** Публічний NASA VOD тривалістю 33 105 секунд;
аналізувалася лише хвилина 1800–1860 с, без повного завантаження VOD. За 113,72 с
отримано READY/cloud_verified, 11,6 с, 1080×1920, 348 декодованих кадрів, звук,
Qwen-метадані та перевірене Drive-збереження. Кліпінг 0, чорні кадри 0, частка
декодованої тиші приблизно 0,92%. Smart Crop: 24 проби, 15 виявлень облич.
Редакторський статус NEEDS_REVIEW збережено; це не схвалення змісту NASA.

**GitHub — PASS для реалізації.** Коміт
[`8f54d07f556c371a530f77e9940c646ca99beb7e`](https://github.com/denusbtw/youtube-temka/commit/8f54d07f556c371a530f77e9940c646ca99beb7e)
відправлено в origin/main. [CI саме цього SHA](https://github.com/denusbtw/youtube-temka/actions/runs/44398229829)
завершився success, backend і frontend success. Перевірка шаблонів секретів пройшла.

**Docker.** Фінальні стандартний controller і web образи зібрано; API й інтерфейс
працюють на localhost:5175. Authenticated settings — 200, anonymous jobs — 401,
Drive підключено; реальні YouTube та Analytics канали виявлено. Публічна й
автоматична публікація вимкнені. Controller, web та Ollama мають healthy; CPU-сумісний controller містить фінальний
код (SHA-256 основних модулів збігається з робочим деревом).

**Новий GPU-образ — BLOCKED зовнішнім завантаженням.** Перша збірка відхилила
пошкоджений pinned CUDA wheel через SHA-256 mismatch. Незалежна повторна спроба
через офіційний PyPI не завершила два великі файли за встановлені п’ять хвилин.
Перевірки цілісності не вимикалися, неповні файли не встановлювалися. Стандартна
CPU-сумісна збірка працює; Qwen в окремому Ollama фактично використовував GPU.
CUDA-ASR у новому образі на цьому 6 GB ПК не підтверджено; попередні успішні
ASR/монтажні завдання могли використати передбачений CPU-fallback.
Мінімальна наступна дія для GPU-образу — повторити штатну збірку через стабільне
з’єднання, потім перевірити CUDA-ASR:
`docker compose -f docker-compose.yml -f compose.gpu.yml --profile controller up -d --build`.
Це не блокує поточний конвеєр і не потребує другого ПК.

## Практичні обмеження

Новий CUDA/ASR Docker-образ не зібраний через зовнішнє завантаження залежностей;
поточний controller використовує CPU-сумісну збірку. Qwen GPU-offload перевірено окремо.

1. Зміст і якість неоднозначних уривків перевіряє оператор. Внутрішня оцінка
   моделі не є доведеною ймовірністю редакторської якості.
2. Встановлення обкладинки залежить від фактичної відповіді YouTube; у цьому
   live-тесті встановлення відхилено. Файл збережено, успіх не вигадано.
3. Для рекомендацій потрібна реальна історія каналу; тестове відео її не дає.
4. Публічну/заплановану публікацію можна виконувати лише після окремого явного
   дозволу власника. Цей реліз нічого публічно не опублікував.
5. Ручна правка тексту мініатюри в метаданих не перемальовує вже створений JPEG;
   для іншого зображення потрібна нова відредагована версія відео.
